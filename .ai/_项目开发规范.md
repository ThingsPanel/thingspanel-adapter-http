# 项目开发规范

## 分层规范

- `cmd/` 放程序入口与辅助命令。
- `internal/bootstrap/` 负责配置加载、日志、平台客户端、协议服务和平台 HTTP 服务启动。
- `internal/protocol/` 负责设备侧协议接入、设备数据解析、遥测转发和协议生命周期。
- `internal/handler/` 负责 ThingsPanel 平台回调处理和平台 SDK 处理器注册。
- `internal/platform/` 封装平台 API、MQTT、设备查询、动态注册和遥测上报。
- `internal/pkg/` 放通用基础能力，如日志。

## 命名约定

- Go 文件、包名使用小写和下划线，导出类型和方法使用 PascalCase。
- 配置字段保持和 `configs/config.yaml` 的 `mapstructure` 标签一致。
- 平台回调相关命名使用 `HTTPServer` 或 `handler`；设备协议接入相关命名使用 `ProtocolHandler`。

## 错误处理

- 对外部系统调用错误保留原始错误并使用 `WithError` 记录。
- HTTP 处理函数需要给调用方返回明确状态码，日志中记录设备号、协议名等定位字段。
- 自动注册、设备查询、遥测上报失败应分别处理，不合并成模糊错误。

## 接口规范

- 设备上报入口归属 `server.port`，默认 `19090`。
- 设备遥测路径固定为 `POST /api/v1/uplink`。
- 平台回调入口归属 `server.http_port`，默认 `19091`，不承载设备上报。
- 设备上报鉴权优先读取 `X-Api-Key`，兼容 `Access-Token`。

## 日志规范

- 项目日志使用 logrus。
- 服务启动日志需要明确端口和服务职责。
- 设备数据处理日志应包含 `device_number`、协议名、数据字段数量和失败原因。
