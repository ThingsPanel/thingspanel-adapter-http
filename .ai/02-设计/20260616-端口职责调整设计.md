# 端口职责调整设计

## 方案概述

将设备上报入口固定收敛到协议服务端口 `server.port`，默认 `19090`；将平台回调入口保留在 `server.http_port`，默认 `19091`。设备遥测路径固定为 `POST /api/v1/uplink`。

## 数据模型变更

无配置结构体字段变更。沿用现有：

- `server.port`：设备上报端口。
- `server.http_port`：平台回调端口。
- `server.http_api_key`：设备上报鉴权密钥。
- `server.auto_register`：设备不存在时是否自动注册。

## 接口设计

- `POST /api/v1/uplink`：设备遥测上报，监听在 `server.port`。
- `/health`、`/healthz`：两个端口都提供健康检查。
- 平台回调：通过 SDK handler 挂载到 `server.http_port`。

## 核心逻辑流程

1. 应用启动时先启动协议处理器，协议 HTTP 服务监听 `server.port`。
2. 协议 HTTP 服务注册 `/api/v1/uplink`。
3. 设备请求通过鉴权后解析 `device_number` 和遥测数据。
4. 遥测解析支持 `values` 嵌套格式，也支持扁平字段格式。
5. 查询设备，必要时自动注册，再调用平台客户端上报遥测。
6. 平台 HTTP 服务监听 `server.http_port`，只处理平台回调和健康检查。

## 新增/修改文件清单

- `internal/protocol/http_handler.go`：注册 `/api/v1/uplink`，增加设备上报鉴权。
- `internal/protocol/handler.go`：传递设备上报鉴权配置。
- `internal/bootstrap/app.go`：区分设备协议服务与平台回调服务启动参数。
- `internal/bootstrap/http.go`：移除平台端口上的设备上报路由。
- `internal/protocol/plugins/examples/http_demo.go`：遥测解析兼容 `values` 和扁平格式。
- `configs/config.yaml`：修正端口注释。
- `README.md`、`README_CN.md`：修正端口职责说明。

## 影响范围与风险

- 设备需要向 `server.port` 上报，不应再使用 `server.http_port` 上报。
- `server.http_api_key` 非空时，设备请求必须携带 `X-Api-Key` 或 `Access-Token`。
